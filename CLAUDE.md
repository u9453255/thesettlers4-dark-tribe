## Orientation

- Read `HANDOFF.md`, then `MAIN.md`, before you change anything. The top section of each describes the current release. Older sections are history only.
- Current release: **0.2.15**. Readiness marker: `Dark Tribe 0.2.15 ready`. Save sidecar schema 2. `DT_Version=200`.
- Game: `S4_Main.exe` in the configured game folder (`DARK_TRIBE_GAME_DIR` or `local-config.json`; see `tools/project_paths.py`), x86, image base 0x400000. Every address in the code is an RVA in this exact pinned build (`tools/game_build.py`). Another build is refused; porting to it means re-deriving every pin by disassembly, never guessing.
- The user does all in-game testing. Never launch, attach to, capture or inject into the game. Only read the existing logs in `evidence/`.
- Runtime log: every line of `evidence/v02-runtime.log` is `<GetTickCount ms> pid=<pid> tick=<AI tick [0xE66B14]> <message>`, and all processes append to that one file. Split by pid first, because GetTickCount restarts after a reboot and pids interleave. Then split by map. A new map logs `New Dark economy initialized` at tick 10 after the tick drops back. A loaded save logs `State restored from matching save hash` and resumes at its saved tick (for example pid 29148 at 67902), so a tick jump inside a pid can also be a load. Identify the build of a process by the round marker its tick-0 startup line ends with. The game trace (`Documents\TheSettlers4\Log\TraceNNN.txt`) prints the same GetTickCount ms in its first column.
- The save sidecar is read back as an exact-size snapshot of `dt::State` (`fread` of `sizeof(snap)`), so any new `State` field breaks schema-2 loads. Keep new feature state transient: re-derive it, or re-adopt native objects after a load as the offence squads do. Add persistent state only with a schema bump and a migration.

## Layout

- `native/dark-tribe.cpp`: the plugin. It contains tick, frame and mouse callbacks, economy, construction ops, aircraft, save hooks and startup guards.
- `native/*-model.hpp`: pure logic, unit-tested by `native/*-tests.cpp`. `build-native.py` compiles and runs these tests.
- `native/*-native.hpp`: pinned engine bridges. These are `construction-native.hpp`, `placement-native.hpp` and `hd-overlay.hpp`.
- `tools/*_pins.py`: list the signature regions. `build-native.py` generates `work/native-generated/*-signatures.hpp` from them, and the DLL checks these at startup and fails closed on any mismatch.
- `tools/inspect-*.py`: file-only disassembly checks with capstone/pefile from `work/python`. Add one whenever new engine facts are relied on.
- `tools/project_paths.py` / `tools/project-paths.cjs`: the only place that knows the game folder and toolchain locations; `tools/setup.py` (one-time setup and pin report) and `tools/workflow.py` (offline workflow) use them. `Launch Dark Tribe.cmd` takes the game path from `runtime/manifest.json`, i.e. the game the build was verified against.
- `work/`, `backups/`, `evidence/`, `runtime/native/*.dll`, `save-states/` and `local-config.json` are ignored and private. Never publish them.
- Scenarios: First Dawn (`build-scenario.cjs` from `dark03`), Iron Kingdom (`build-iron-kingdom.cjs` from `AO_trojan10`, `research/IRON_KINGDOM_0215.md`) and The Alliance (`build-alliance.cjs` from `dark07`, 512x512, four players, `research/ALLIANCE_0215.md`). `tools/scenarios.py` lists source pins, files, map size and race/start of every player; `native/scenario-model.hpp` repeats the layouts for the scene fingerprint (`verify-offline.py` checks both agree). A new scenario needs: a supported map size (`dtmap::Sizes` in `native/map-size.hpp`: 512, 576), human Dark Tribe player 1 as the only Dark player, every other player a computer (slot/team table `00 01` then `01 02` per computer player), every computer entrance and unit on its own initial land, and a `DT_Version = 200` script without `for` loops (the game's Lua 3.x). It also needs a clean start: no Dark Mushroom Farm (map type 49) closer than FarmLock (Euclid 33, `dtfire` in `native/citadel-fire.hpp`) to the fire centre (position + (1,2)) of a Dark Temple (50) or Fortress (51). The Manacopter Hall (80) has no fire and does not count. The builder removes such farms with `removeFarmsInFire` from `tools/citadel-fire.cjs` (the record plus the flags 0x0B that the editor baked under it), and its test asserts the result and rejects a farm put back inside. `verify-maps.cjs` checks every `SCENARIOS` entry. The plugin's start-tick crush (`FARM_FIRE_REMOVED`) is only a safety net. Add it to both lists, give it a builder and a `test-*.cjs`, and append it to `SCENARIOS` (the installer upgrade adds it to existing installations).
- The launcher helper must assign the human slot in the lobby, before the map loads; a late assignment starts the map without a local tribe and the HD patch crashes (`Current Tribe: 255`). Never make `activate-human-slot.py` depend on values the engine writes during map load, such as the view map size.
- Map size: never use a fixed map side. Use `side()`/`dtmap::size(image)` (engine stride RVA 0x1054138, equal to the view size 0xD6921C), which is 0 without a supported map.
- Map grid: cells are axial hex coordinates used directly (index `y*N+x`). The six neighbours are (±1,0), (0,±1), (+1,+1) and (−1,−1); (+1,−1) is 2 steps away. Never use the textbook axial diagonal (+1,−1) or odd/even-row offsets. Distance is `dt::distance` (offence-model.hpp) = max(|dx|,|dy|,|dx−dy|). A ring has 6r cells and a disc 1+3r(r+1). A square loop over [−r,r]² is a rhombus that reaches 2r, so filter it with `distance()`. For Euclidean geometry embed X = x − y/2, Y = 0.866·y, as `detour()` does. On screen, (x+1,y) is right, (x,y+1) down-left and (x+1,y+1) down-right (tested in game by the user's collaborator). Pixel positions need the projection RVA 0x259910, which includes terrain height.
- Runtime per-cell arrays are flat N×N with index `y*N+x` and row stride RVA 0x1054138. Landscape 0x11630D4 has 4 bytes per cell: byte 1 terrain, byte 2 bit 0x40 Dark, byte 3 fog. Flags 0x11630D8 have 1 byte per cell. The ground-entity map 0x11630DC holds a uint16 entity id per cell, and the object map is at 0x11630E0. The SU API reads a walk-sector WORD at 0x11630D0. The engine's own sector lookup (0x169F90) reads the tile map [0x11630C4] and the 20-byte sector records at 0xEF1A20. Size every read from `dtmap::size()`. Map-file chunk bytes mean something else: chunk 6 byte 0 spawns objects, byte 1 seeds the initial sector/owner map, byte 2 the flags and byte 3 the resources (research/STARTUP_SECTORS_025.md). Never reuse them for runtime bytes.
- Scenario Lua is Lua 3.2.1. `S4_Main.exe` embeds the string `Lua 3.2.1`. Its reserved-word table has `while`, `repeat`/`until` and `elseif` but no `for` or `break` (file check). The Lua math library is not registered: the exe has no `abs`, `mod` or `randomseed` names. The string functions and `foreach`/`foreachi`/`getn`/`tinsert` are present. Besides `for`, avoid `break`, `true`/`false` (use nil and 1), `#`, `local function`, `ipairs`, `%` (upvalue syntax in 3.2, not modulo), `_G`, `select` and every math call. Write helpers such as `abs` with `if`; the user and a collaborator use a global `abs` plus `HexDistance` in their own scripts. `while` is a valid keyword, but no shipped Dark Tribe script uses it. `test-scenario.py` runs the scripts under modern Lua (Lupa), and `verify-offline.py` refuses only `for`, so an offline pass does not prove 3.2 compatibility.
- Map files: `tools/map-format.cjs` `readMap(file).chunks` returns the decoded chunks. Chunk 1 holds gameType at +0 (0 multiplayer, 1 single player, 2 cooperation; enum from the vendored settlers-ts), the player count at +4, startResources at +8 (1..3) and the map size at +12 (dark03: 1 2 2 576). Chunk 2 has 45-byte player records with the race at +0 and the start at +4/+8. Multiplayer maps carry race 255 there. Turning one into a scenario probably needs gameType 1 and explicit races, but this has never been tried. The vendored decoder prints `StreamWriter Read before data` noise. Three installed maps fail with `Invalid compressed stream` (Campaign/XMD3_trojan4, User/CM_abandon_all_hopes, User/Mountains And Lakes), so wrap folder surveys in try/catch. Scratch `.cjs` scripts outside the repo must `require` map-format.cjs by absolute path.

## Construction (0.2.14)

Successful construction completes the **same native site in place**. Nothing is deleted or recreated. The 0.2.13 approach (mode-1 cancel, then `BuildingsAdd`) failed because units walked into the released footprint.

On payment, the mod:
1. Freezes `CBuildingSiteRole` at phase 1.
2. Detaches the ordinary requests for Temple and Fortress (slot 11).
3. Applies the reservation (RVA 0x136470) once.

It then draws the kind's growth time (`growthTicks()` in `construction-model.hpp`: Farm 40, Hall 60, Temple 80, Fortress 100 ticks; `GrowthTicks` 30 is only the minimum) and completes the site with the native sequence for its kind:
- Farm and Hall: the grow-path phase-8 steps.
- Temple and Fortress: RVA 0x1424C0 and 0x1429F0 when the site has an economy. Without one, the mod removes the material piles itself and then runs the phase-8 steps.

Wild animals (class 0x80, owner 0; Dark-land critters) never block completion except on the anchor tile (native checks occupancy only before claiming cells). The mod waits while units stand on the site and every 20 ticks orders its own idle units off the footprint (`evict`), because idle units never leave reserved cells by themselves. A static blocker gets one refund, then the site is cancelled with mode 1. Mod-issued moves set `internalSend` so the send callback ignores them.

Once a site is reserved, never re-check the placement flag bits on its own cells. When an object is created next to the site (for example a mushroom a Mushroom Farmer plants), RVA 0x163510 sets keep-clear bit 0x40 on the surrounding cells, including the site's own. Re-checking that bit refunded growing Farms. Check only occupancy, as native phase 7 does. Log a block reason before you refund or cancel, because cancelling changes what the log can see afterwards.

`research/CONSTRUCTION_INPLACE_0214.md` documents every native field and RVA, and `tools/inspect-construction.py` checks them. Before you change this code, re-verify each native behaviour you rely on by disassembly. Do not guess.

The AGENTS.md bullet about "Foundation conversion uses Lua cancellation mode 1 ... original-identity disappearance" describes the replaced design. Mode 1 is still used, but only for refusals and refunds.
- The native Dark validator (RVA 0x13EBC0) rejects anchors with x or y below 15 or above size−16 before any cell test; the placement hints clip to 16..size−16. Exclude that margin in placement scans and map tools.
- r34: the plugin tick runs once before each input batch, so a site created by a build event can be clicked before any tick sees it (crash 0x143E07). The site panel (CBuildingSiteRole slot 22, entry RVA 0xC59214) is therefore wrapped at startup by `dtconstruction::PanelGuard`: without an economy at the entrance it runs the native panel on a transient info copy (no inhabitant/tool, piles 0) and restores the fields. Keep the wrapper heap-free, lock-free and log-free; never write the global info table (completed roles read +0x1DE).

This is not the lobby slot type of the scene fingerprint (session +0x90, which is 1 for computers). On Easy, CAIAgentRecruitment orders only level-1 swordsmen/bowmen and squad leaders. It jumps past the race specialists (0x32E20), and CAIAgentSquads requests no race weapons (0x34371), so battleaxe and blowgun piles only help on Normal. Which value the scenario computers get is untested (research/AI_OFFENCE_0215.md, Limits r28), so set all three `AI.SetPlayerVar` columns deliberately. Never set `AI.SetFlagBits` bit 0: it switches off the native economy AI.
- Computers can come to own Dark cells through pioneers (claim 0x17F0A0, whose cell mask 0x99 at 0x17F020 lacks the Dark bit 0x04) and through vehicle claims (0x15DAE0), not only through towers. `[0x101ECB4 + 4p]` (updated by SetOwner 0x1B79A0) is not an exact owned-cell count; use it only as a change trigger. 0x13F210 is only the shipyard/port placement (types 0x1F/0x20). Keep the band scan (`scanTerritory`). Evidence: work/native-analysis/ai/r5/v/verify_corrections.py.
- The fake engine in `native/offence-tests.cpp` teleports moves and greens only reserved ring cells. In r27 it passed while real gardener defects existed: the native-faithful simulation showed 19 of 64 sieges over 9,000 ticks. That simulator is `work/native-analysis/ai/scripts/review4/model_sim.cpp`. It models the exe spiral, gardener search, drift and give-up, formation slots click+2*spiral, and real footprints. It was written for the r27 model and no longer compiles against r28 `offence-model.hpp`: its fake Ops lacks darkFighters, ownDark, call, announce and reach, and KeepOff is gone. Port it before using it for gardener or army steering changes, and keep the adversarial review with one verifier per finding.
- Field timing: farm sieges in the user's sessions took about 700-3,500 ticks (median 1,200-1,700) and a Temple about 2,200, several times the old estimate; the tick rate per wall second varied from 14 to several hundred (likely game speed). Reason and tune in ticks, never in minutes (measurements in research/AI_OFFENCE_0215.md).

## Performance and input

- Read memory through `dtmem` (`native/fast-memory.hpp`). Inside `tick()`, a `dtmem::Scope` caches queried memory regions. Call `dtmem::invalidate()` after any native or API call that can free memory.
- Never add a raw `VirtualQuery` per read: a single uncached scan of 65,536 entity slots costs about 40 ms.
- The HD renderer does not deliver the old draw (blt) callbacks, so sprite hit-testing doesn't work under HD. Resolve map-targeted actions through the `send` callback's map position instead (for example, boarding when units are moved onto an aircraft).
- Construction start must not repeat the placement-flag test. The game's site setup changes those flags on its own cells.

- r41: the native CManakopter update heals a landed aircraft on a Dark cell to DTManakopterHitpoints every 10 ticks (0x16B58F..0x16B597); `installNoHealing` NOPs that store at startup (pinned, fail-closed, idempotent) because the user wants no regeneration. Keep it when touching aircraft code, and never add a plugin-side heal.
- Manacopters cannot be put in native selection: their selection group bits (low 4 bits of `+0x14`) are 0. The mod keeps its own `fleetPick` group, resolved on the tick through the projection (RVA 0x259910). Before adding a command number, check `panel.hpp` `hit()` for ones already in use.
- Construction drawing: native draws a site only from a map-layer anchor. Grow sites (Farm/Hall) are anchored in the object layer. Ordinary sites (Temple/Fortress) are anchored in the building layer at native phase 4, which the mod mirrors.

- Native UI and order code often assumes an ordinary settler economy at a building's entrance, and Dark land has none. Before letting players interact with a native object, look for `[edi*4+0x146c8a4]` (economy table) reads. Examples are the site panel (slot 22) and pause (slot 8).
- Passengers must go through the native arrival sequence: mode +0x42 = 0xA, then scheduler removal at RVA 0x16D720, then board at RVA 0x16B890. Calling RVA 0x16B890 alone leaves the unit walking on the map. r39: the native unload (0x16B990) only posts events 0x19/0x11 to each passenger; a role whose event handler (role slot 14, +0x38) does not know 0x19 never leaves the hidden state. Soldiers and Shamans do (CHJBRole 0x189F70); Dark Gardeners (CDarkGardenerRole 0x174F10) do not, so `placeUnloaded` mirrors the soldier case for them (0x182A40, 0x1BB560, flags &= ~0x8000 | 0x2100). Any new boardable kind needs the same check of its role's handler.
- Fog: the fog manager (RVA 0x1159D30) keeps a byte map at +0xC. Bits 3-5 are pending visibility; bits 0-2 are the current level, which is merged into land byte 3. For temporary unit vision, call RVA 0x1AE100(x, y, radius) every tick, as the native band pass does.
- Never use slot 7 (sets the current level permanently) or slot 15 (appends persistent saved entries). Never clear land byte 3 bits around units.
- Fog merge (r35, `research/DARK_SIGHT_FOG_0215.md`): land byte 3 bits 3-5 are the shown level (0 visible, 3 explored, 7 black), bits 0-2 the previous one. The merge 0x1AE3F0 skips the land write for 8-cell groups whose fog bytes counted three stable cycles (bits 6-7 = 0xC0), so any level the plugin writes stays until that counter is cleared. The Dark-land visibility (`dt::darkSight`) clears the counter (`fog[i]&=0x3F`) of every cell that stops being Dark, so the native merge re-fogs it; keep that hand-back whenever land byte 3 is written. r42: the Alt+9 reveal clears only the pending bits 3-5 of every fog byte each tick (`dt::revealPending`), never the base bits 0-2 (saved explored state) or the counters; keys are polled on the tick with `GetAsyncKeyState` (no SDK keyboard callback), foreground process and `inGame()` only.

- The game sends no move order (the `send` callback) when its own selection is empty. Orders for mod-only selections, such as Manacopters, must come from the mouse callback and be resolved on the tick.
- The game must be closed to rebuild: a running game locks `runtime/native/DarkTribe-*.dll`. Never stop the user's game; ask them to close it.
- Crash and freeze diagnostics (r26, `native/diagnostics.hpp`): the vectored handler, the freeze watchdog and the process-exit path must stay heap-free and loader-lock-free, because they run while the game's heap may be corrupt or locked. Build lines with `dtdiag::Text`, write them with `dtdiag::write`, and read memory with `dtdiag::SafeRead`; never call `log()` (it uses `fopen`) or allocate there. `tools/test-diagnostics.py` checks this in a disposable fixture. WinDbg is not installed: read WER dumps (`%LOCALAPPDATA%\CrashDumps`) and freeze dumps (`evidence/freeze-*.dmp`) with `tools/read-crash-dump.py`.

- Selection brackets come from each entity's draw method (CSettler slot 5 fills the draw descriptor at RVA 0x129ADFC when flag 0x200 is set). Manacopters have no such path, so the mod draws `dtui::markerPixels` itself (`dthd::Markers` under HD). Never set 0x400 on aircraft: it triggers a virtual call (+0x94) that does not exist in the Manacopter vtable.

- The HD host thread must survive the game window being replaced: `Host::run` re-attaches, and it logs `HD_PANEL` show/hide reasons. Keep both when changing the overlay. Manacopters always carry flag 0x8000, so "hidden" means class 1 with 0x8000 only.

- UI: the Dark menus use the game's own sprites, loaded read-only from the game's `Gfx` folder by `native/gfx-assets.hpp` with per-range SHA-256 pins from `tools/gfx_pins.py` (add a sprite there, then to `dtgfx::Art`). Layouts copy the native menus in `Menu/GUISetRomans.DAT` (`python tools/guiset.py Romans <menu>` lists them; format notes in that file). Draw through `panel.hpp` (`background`, `title`, `separator`, `iconButton`, `action`, `portrait`, `picture`, `vbar`, `label` with fonts F1..F14) so every element has a drawn fallback when the art is unavailable. Resolve settler sprites by animation name through the engine table (RVA 0xC00974, job = id - 1), never by eye. Never commit game-derived images: previews with real art go to `work/previews/`. Never draw pure black (the HD colour key). The Dark unit panel lives in `native/unit-panel.hpp`; its commands are 40..49, handled in `unitCommand` on the tick.
- Mouse: the S4ModApi mouse callback never sees WM_MOUSEMOVE. Always pass the game a right release whose press it received (its pan state is set on press and cleared only on release); decide click vs drag with `dt::rightClick` (4 px, the game's own pan threshold).
- Text: `panel-tests` checks every label per glyph against the measured frame bounds (`InnerX0..InnerY1`, title box) in both art modes; keep it at zero failures when changing layouts. Temple/Fortress recruitment commands are 21 (select, UI only) and 22 (order with amount; 100 = the game's own continuous recruitment).
- Layout: Dark menus cover y 210..599 (panel #589) and the mana section covers the native resource panel y 600..767 (#587) whenever the plugin is active; the HD canvas is 200x768. Construction allows one Dark Temple and one Dark Fortress (`buildLimit`, enforced on command 1 and on new sites). Aircraft panel command 37 keeps one aircraft.
- Ticks stop in the menus: never rely on tick-cached scene state alone to show UI. Gate every display/input path with `inGame()` (frame callback screen check, tick fallback).
- Player texts: `say()` only for failures, in player language, never versions, log paths, coordinates or internal states; notices vanish after `NoticeMs`. Keep the scenario script silent on load.
- Never put a `//` comment inside the long single-line statements in `dark-tribe.cpp`; it silently comments out the rest of the line. Use `/* */`.
- Settler types 49-51 (other races' Geologist, Gardener and Landscaper) have the same numbers as the Dark building kinds 49 Farm, 50 Temple and 51 Fortress (the Hall is 80). Test the entity class (byte +0x0A: 8 building, 1 settler) before treating a type as a building kind. Dark settler types: 29-31 Warrior, 32-34 Thrower, 52 Dark Gardener, 53 Mushroom Farmer, 54 Shaman, 55 enslaved settler, 56 Servant, 66 Manacopter pilot. Computer Gardeners are type 50.
- Shaman spells exist only as research (`work/reports/Dark Tribe shaman spells.md`, not pinned). The Dark spell row has only Rot (slot 2, RVA 0xF4C70) and Teleport/theft (slot 7, 0xF4D10). Slot 7 without a live Shaman caster dereferences null (0xF4D61), so never call Lua `Magic.CastSpell(p, 3, 7, ...)` or S4ModApi `MagicCastSpell(S4_TRIBE_DARK, S4_SPELL_7, ...)`; the 1-based enum lands on slot 7. A Shaman's mana is its role's own pool at +0x68 (S4Forge.RE's +0x6C is the debug build's layout), and it refills on Dark land.
- Never put a `//` comment inside a long single-line statement in any native file (dark-tribe.cpp, the one-line `struct Data` in panel.hpp, hd-panel-preview.cpp): it silently comments out the rest of the line. Use `/* */`.

## Build and verify (offline only)

Run the full list in `HANDOFF.md` ("Primary offline workflow") with one command:

```bash
python tools/setup.py --check   # toolchain, game pins and config; without --check it downloads/installs what is missing
python tools/workflow.py        # every offline build/check step in order; stops at the first failure
```

Node.js comes from `DARK_TRIBE_NODE`, `"node"` in `local-config.json` or PATH (record one with `python tools/setup.py --node <node.exe>`). When running single steps by hand, call the `.cjs` steps with that node; `verify-offline.py` finds it the same way.

- The compiler is `work/native-sdk/compiler/llvm-mingw-*/bin/i686-w64-mingw32-clang++.exe` (`project_paths.COMPILER`), and `build-native.py` invokes it. `tools/setup.py` downloads it with the hash in `research/compiler-download.json`.
- Pins must end on instruction boundaries and must not cut a relocation. The pin generator raises an error on a truncated relocation.
- When you run disassembly helper scripts, do not name them after stdlib modules. A script named `dis.py` breaks capstone's import.
- Before `build-native.py` or `stage-release.py`, check that the game is closed (`tasklist //FI "IMAGENAME eq S4_Main.exe"` in Git Bash). While it runs, compile a scratch DLL instead (`<compiler> -std=c++17 -O2 -static -fms-extensions -Wall -Wextra -shared -Iwork/native-sdk/S4ModApi -Iwork/native-generated native/dark-tribe.cpp work/native-sdk/S4ModApi/S4ModApi.lib -lgdi32 -lmsimg32 -lbcrypt -o <scratch>/check.dll`, or use `-fsyntax-only`), run the model tests, and tell the user plainly that nothing is staged. The user once tested a stale r8 build twice because r9 could not be staged.
- Inspectors assert source text. `inspect-interactions.py` refuses the substrings `stock`, `cargo` and `courier` anywhere in panel.hpp, identifiers included, so name passenger fields rider*/passenger*. Several `inspect-*.py` slice `dark-tribe.cpp` between text anchors (e.g. `struct OffenceOps {` to `static HRESULT __stdcall frame(`). When moving code or changing wording, update the anchors and check that each asserted string really occurs; one review found a vacuous `image+0x45020` check. If verify-offline misses a literal log marker, look at how the string is emitted: clang -O2 copied constant tags in vector chunks until `Text::put` got `noinline`.
- Whole-section capstone scans (all writers of a flag, xrefs) need `md.skipdata = True`. Without it, the linear sweep stops at the first data bytes in .text and silently finds nothing.
- `runtime/manifest.json` and several `research/*.json` reports are rewritten by every build. They hold the DLL and inject.exe hashes, the local game path and regenerated check data, and Git warns about LF→CRLF because core.autocrlf is on. So they show as modified after any build. When the user asks for a commit, include them with their release. Don't revert them or treat them as user edits.
- `tools/workflow.py` holds the authoritative step list (HANDOFF's "Primary offline workflow" mirrors it, including `test-diagnostics.py` right after `build-native.py`). `build-native.py` takes about 40 s and the full workflow about 3-4 minutes, so run it in the background or with a long timeout.

## Releasing a version

Bump every version and readiness marker together. These appear in the native sources, the tools, the scenario, the HD panel class name, `startup-status-0XYZ.json`, `V0XYZSessionHelper`, and README/MAIN/TESTING/HANDOFF. `verify-offline.py` enforces them.

Each release also needs:
- a new MODLOG entry;
- a research note;
- a TESTING.md section with the user's test steps;
- staging with `tools/stage-release.py`. This never touches the live game; the user activates the release with `Launch Dark Tribe.cmd`.

Do not commit, publish or message anyone unless the user asks.
- A rebuild without a version bump is a round: r3-r11 in 0.2.14 and r12-r43 in 0.2.15. For each round: append `; <summary> rN` to the startup log line; add a TESTING.md "rN checks" section; add a MODLOG.md "Round rN: ... (date, still 0.2.15)" entry; add a HANDOFF.md/MAIN.md "Round rN (0.2.15)" section. Tell the user the exact suffix to look for. Bump the version only when the user asks (0.2.15 was a user request). Confirm staging with `python -c "print(b'<marker>' in open('runtime/native/DarkTribe-<v>.dll','rb').read())"`. When a user report contradicts the code, first check which marker that pid's startup line ends with.
