# Instructions for agents working on this mod

Read `HANDOFF.md`, then `MAIN.md`, before changing code. Use the current source and manifests to verify historical notes. Version-specific reports in `research/` and older sections of MAIN.md/HANDOFF.md/MODLOG.md describe earlier implementations, not current behavior.

- Work in this repository. The game is the folder configured by `DARK_TRIBE_GAME_DIR` or `local-config.json` (written by `tools/setup.py`, resolved by `tools/project_paths.py` / `tools/project-paths.cjs`; fallback `C:\Projects\thesettlers4`, the original author's writable copy). Never hard-code a machine path in tools. Do not move the game, change its install location or redirect Ubisoft Connect without the user's instruction.
- The user reserves **all in-game testing**. Do not launch/control/capture the game, inspect its live process or inject modules for testing. Build, inspect files, read existing logs and run offline/disposable non-game tests. Give the user final test instructions in `TESTING.md`. A future explicit user instruction may change this restriction.
- Scope is a dedicated playable Dark Tribe scenario first. Ordinary new-game race selection is outside the current release. Preserve the requested real production/delivery economy, repeatable construction, base recruitment, Dark-only building menu and Dark-land visibility. Do not bring back prototype timed resources/waves or a fixed one-use farm pad.
- Dark Tribe start maps must be clean: no Dark Mushroom Farm within FarmLock (Euclid 33, `native/citadel-fire.hpp`) of a Dark Temple/Fortress fire centre (the Manacopter Hall has no fire and does not count). Builders clear such farms (`tools/citadel-fire.cjs`) and map tests assert it; the runtime crush (`FARM_FIRE_REMOVED`) is only a safety net.
- Native Mushroom Farmers already handle production and delivery. Do not assign extra Shamans/couriers, invent Farm stock/cargo or intercept native farm credits. Schema-2 Farm fields are legacy save compatibility only. Preserve the separate Manacopter passenger menu.
- Never describe offline success as verified gameplay. The second-farm crash cause and the effectiveness of the 0.2.2 safeguards remain unconfirmed. Preserve evidence and distinguish confirmed defects, hypotheses and observed user outcomes.
- Keep the executable/API hash guards, scenario fingerprint, entity identity checks, transaction checks and save-sidecar validation. Do not guess addresses for another build. Recycled pool IDs alone are not safe identities.
- Settlers United changes the verified executable only by its LAA header bit. Accept only the two full-file pins in tools/game_build.py; never mask arbitrary changes or rewrite the game. Select the exact pinned game-folder API when present so SU and this addon share one API. Preserve SU plugins/settings and runtime signature checks.
- Foundation conversion uses pinned Lua cancellation mode 1. Mode 0 is cleanup without entity deletion. API void-wrapper BOOL confirms Lua dispatch only; retain original-identity disappearance and collision checks. Skip deletion-marked UIDs and never recharge a refunded/refused retained foundation.
- Construction uses the native BYTE flags and Dark terrain rules, not LandscapeIsOccupied (walking sectors). Retain full masks, physical margin and real entity blockers. Dark placement hints scan the native cache on ticks, with bounded work and existing-entry reuse; never alter ordinary territory to obtain green circles.
- Startup/file hash checks must use this DLL's own Windows imports; never call uninitialized game save-hook originals. Preserve the pre-hook hashing fixture and failed 0.2.11 evidence.
- HD menus use an owned, non-activating layered panel with the shared renderer; the old DirectDraw surface alone is insufficient under HD. Panel rendering/input reads cached tick data and queues intent only. Preserve exact HD DLL pins, DPI/hit mapping, focus/scene hiding and the native non-HD fallback; do not change SU files/settings or add guessed renderer hooks.
- Lua and gameplay mutation belong on game ticks. Rendering uses cached data; frame/mouse callbacks must not wait on the economy lock or call Lua. Preserve automatic farm-worker recruitment when changing manual queues.
- Preserve original backups and user saves. Never overwrite unrelated changed game files. Installer/restore logic must retain upgrade/refusal/rollback checks. Keep `.sav` files and matching `save-states` sidecars together.
- After relevant changes, run the offline build/checks described in `HANDOFF.md`; update `MAIN.md`, `MODLOG.md`, research notes and `TESTING.md` with outcomes and limitations. Update all version/readiness markers together for a release.
- Private game-derived XML, maps, disassembly, binaries, backups and saves stay local in ignored folders. Do not publish them. No publication or messages to other people are authorized by this project.
- Communicate in English, briefly and directly. Avoid filler and unnecessary approval questions. Show the concrete result and its evidence boundary.
