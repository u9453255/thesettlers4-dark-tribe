# Construction, mana and selected Manacopter transport — 0.2.8

2026-10-12. Current code/build scope only. No game launch, control, capture, live process inspection, native game injection or live installation. All gameplay acceptance is reserved for the user.

## Confirmed source/file defects and corrections

The former menu started every outline without affordability checks. Foundations below their cost waited for future income. The new menu and tick processing check delivered mana (25/100/150/120), reject unpaid foundations, charge accepted jobs once and verify the resulting bank. The bank target preflight also refuses integer overflow/underflow.

The pinned Buildings.Delete Lua dispatch at RVA 0x1C5EDF sends mode 2 to the native destruction path at 0x136A80. That path creates destruction objects, with a separate Farm graphic and a larger generic graphic. These can obstruct the original footprint guard. Mode 0 instead invokes the building's native removal entry without that destruction path. Paid/rejected foundations now use mode 0; normal player demolition is unchanged. Completion still requires original site identity disappearance, 30 settling ticks, full original masks/halo, Dark/terrain bounds and absence of units/objects/other building footprints. Blocked work refunds once after the existing timeout. The full cause of the user's non-completion and earlier construction crashes remains unverified.

The old positive-income entry at RVA 0x36380 is reached by the AI extra-mana/catch-up branch at 0x3B33E, conditioned on its low bank. The ordinary native credit at 0x389C0 belongs to CAIMain's vtable and directly adds the per-player native amount from its configuration field +0x2C to the XOR-encoded bank. It does not call 0x36380. The former mod therefore intercepted the wrong path and allowed the direct native credit through. The new guarded six-byte trampoline diverts the exact direct credit once into pending harvest/stock and suppresses synthetic player-1 catch-up grants. Other players and inactive scenarios retain native behavior. The ordinary walking delivery path remains the sole bank credit for this production, with conserved inventory/loss accounting and exact transaction checks. Farm creation and ticks themselves award no new mod resources.

Attribution still follows native Farm cycle hints and divides ambiguous simultaneous income among active Farms; exact individual-farm attribution remains a gameplay limitation. The aggregate conservation invariant is retained. Existing saved balances may already be inflated; there is no evidence to reconstruct and subtract prior credits safely, so they remain unchanged. Use a new game to validate the repair.

The pinned [S4ModApi 2.3 scripting source](https://github.com/nyfrk/S4ModApi/blob/v2.3/S4ModApi/CS4Scripting.cpp) already uses DecreaseMana for negative changes. An early hypothesis that negative payments were ignored was discarded. Existing runtime logs containing charged construction are consistent with that wrapper; they are not a test of this release.

## Aircraft interaction

The existing [Blt callback implementation](https://github.com/nyfrk/S4ModApi/blob/v2.3/S4ModApi/CBltHook.cpp) reports rendered entity IDs, zoomed destination bounds and fog state. A nonblocking callback matches those IDs to a tick-cached owned aircraft identity and records its current drawn rectangle. Mouse input uses fresh cached rectangles (250-ms expiry) to queue selection/boarding. Bounds merge only within one rendered frame and are replaced the next frame. No guessed screen-to-map formula or Lua call is added to rendering/input. Left-click selection clears the unsupported native selection on a tick; the existing native destination callback supplies right-click flight coordinates. The roster tab/Hall button and independent coordinate/Fly controls remain available through Destination/Cargo menu, so dispatch through a native mouse command is not the only flight route.

Right-clicking a landed craft with selected owned Warriors/Throwers/Gardeners/ordinary Shamans queues only those IDs plus identities. Orders validate living ownership/type/identity, exclude couriers/Farmers/hidden units, reserve no more than six cargo slots, issue normal movement toward clear tiles within the boarding radius and invoke original native boarding only within six coordinate units. New ordinary movement cancels affected orders; aircraft flight/unload cancels its approach orders; blocked orders expire after 600 ticks. They never create substitute units. Boarding validates passenger count growth and removes successfully loaded units from native selection.

The menu reads the native 12-byte passenger records on ticks and displays type/ID after checking current identity, kind and ownership. Unload preserves the native exit ring and now checks the actual ground entity map as well as terrain/object guards. Native passenger/save representation is unchanged; sidecar schema stays 2. Pending approach orders are transient and cleared on map initialization/load; they must be reissued after loading. Actual sprite-ID dispatch, camera/zoom picking, movement/landing, native boarding/unloading and passenger reload remain user acceptance.
